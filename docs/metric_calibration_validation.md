# 米制标定流程验证（公开真值集，另一域）

**这不是本项目的标定。** 本页用公开数据集验证「相对深度 → 米制距离」的**流程**是否成立、
误差如何分布、以及哪些先验假设站得住；它**不产出**本项目摄像头的标定参数，
也不能作为 `MetricEvidence` 的支撑（`support_id` 必须指向本机在固定安装条件下的测量记录）。
任务 D 的正式标定仍等待相机确定后进行。

## 目的与做法

- 目的：在**不占用用户时间、不依赖未定相机**的前提下，先把任务 D 需要的机制验证清楚：
  控制点采样 → 仿射拟合 → 反演 → 区间外拒绝 → 误差随距离的分布。
- 数据：iBims-1（[TUM 官方页](https://www.asg.ed.tum.de/lmf/ibims1/)，LiDAR 真值的室内集，
  100 个场景、640×480，含相机标定参数）。它属于**另一域**（DSLR + 激光扫描、非本机摄像头）。
- 深度路径：与应用一致——`configs/system.ini` 的 `[depth]`（Depth Anything V2 Small 本地权重，
  输入 518），用生产 `DepthAnythingV2Estimator` 推理，不做任何改码。
- 控制点：每场景 40×40 分块取中位数（近似融合里「区域内 中位数」的统计量），
  剔除饱和值、有效占比 < 0.8 与中位数 ≤ 0 的块；共保留 17,687 个控制点、跳过 1,513 个。
- 划分：按场景奇偶分成拟合半集（50 场景）与留出半集（50 场景），避免同场景泄漏。
- 择优规则：**两种候选函数形式都拟合**（`r ≈ a·(1/Z)+b` 与 `r ≈ a·Z+b`），
  用**留出集误差**（AbsRel 更低者）选定，而不是靠相关系数或先验假设。
- 指标：iBims-1 官方排行榜同一套**尺度无关**口径（rel、log10、RMS、δ1/δ2/δ3）。
  归档中的 `depth.png` 单位未在可访问文档中写明，尺度无关指标不受该歧义影响；
  RMS 以「数据集单位」标注。

## 结果（留出 50 场景，8,899 个控制点）

| 方案 | AbsRel | log10 | δ1 | δ2 | δ3 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 直接当米用（未标定） | 0.9998 | 4.178 | 0.000 | 0.000 | 0.000 |
| 只拟合全局尺度（无截距） | 6.860 | 0.527 | 0.141 | 0.261 | 0.378 |
| **单一全局仿射（本次选定的形式）** | **0.517** | **0.145** | **0.562** | 0.794 | 0.893 |
| 同一仿射，且只统计落在拟合区间内的点 | 0.491 | 0.144 | 0.562 | 0.794 | 0.893 |

选定形式（由留出集误差决定）：`r ≈ a·Z + b`，`a = −8.33e−5`、`b = 5.889`，
拟合半集 R² = 0.709；另一种形式 `r ≈ a·(1/Z)+b` 的 R² 仅 0.280，留出集 AbsRel 1.00、
log10 9.35（实质失效）。可反演比例 94.9%（5.1% 的点给出非正值 → 按设计拒绝）。

按真值四分位分档（区间以数据集单位计）：

| 真值分档 | 点数 | AbsRel | log10 | δ1 |
| --- | ---: | ---: | ---: | ---: |
| 最近 25% | 1,889 | 1.608 | 0.322 | 0.200 |
| 次近 25% | 2,110 | 0.354 | 0.166 | 0.375 |
| 次远 25% | 2,224 | 0.175 | 0.080 | 0.704 |
| 最远 25% | 2,225 | 0.088 | 0.040 | 0.904 |

## 这些数字告诉我们什么（对任务 D 的意义）

1. **未标定的相对深度不能当米用**：AbsRel ≈ 1.0、δ1 = 0 —— 与本仓库红线一致
   （AGENTS §6：相对深度不是米制距离）。这是用真数据复核的，不是引用。
2. **只拟合尺度不够，截距不可省**：只拟合一个全局尺度时 AbsRel 6.86、δ1 0.141，
   远差于同时拟合截距的 0.517／0.562 —— 与「逆深度仿射歧义」需要两个参数的说法一致。
3. **不能预设函数形式**：本次数据支持的是 **affine-in-Z**（R² 0.709），而方法资料
   （[单目相对深度↔米制尺度标定](https://raw.githubusercontent.com/eugenewang5425/embodied-ai-lab/refs/heads/main/docs/25-session-23-monocular-metric.md)）
   假设的是 affine-in-1/Z（本次 R² 仅 0.280）。因此本机标定必须**同时拟合两种形式并用实测
   留出误差择优**，而不是照抄公式。
4. **单一全局标定在近距最差，而近距正是本项目最关心的**：最近 25% 分档 δ1 仅 0.200、
   AbsRel 1.61，最远 25% 分档 δ1 0.904、AbsRel 0.088。这解释了为什么任务 D 必须给出
   「有效区间」并在区间外返回 `None`，而不能给全距离一个数。
5. **区间外拒绝机制有效**：本次用拟合半集真值范围 ±10% 作为区间，留出集 8,894/8,899 落在
   区间内、5 个在外；落在区间的点误差略低于全体（0.491 vs 0.517），说明「先判区间再输出」
   不会掩盖误差，但也不足以把误差降到可用水平。

## 局限（不得与已发表的排行榜数字直接比较）

- 属于**另一域**：DSLR + 激光扫描、室内场景、与本机摄像头内参和安装条件无关；
  **不能**用这里的 (a,b) 作为本项目参数。
- 未使用官方提供的「无效/透明/平面区域」掩码（其 PNG 语义未在可访问文档中写明），
  只用饱和值与有效占比过滤，因此控制点里可能混入窗户、镜面等区域。
- 控制点是 40×40 分块中位数，**不等价于目标检测框**（本项目融合统计的是目标框区域）；
  没有接入 YOLO 检测，也没有按类别分组。
- 指标为尺度无关口径，因为归档未标定单位；RMS 只能以数据集单位给出。
- 已发表的 iBims-1 排行榜（如 Eigen 2014 rel 0.32／log10 0.17、Li 2017 rel 0.22／log10 0.11）
  使用**逐图尺度与偏移对齐**，而部署时无法知道新场景的真实尺度，只能用**单一全局**参数；
  本次结果（rel 0.517）与该口径不可直接比较，这一差距本身正是「全局标定更难」的证据。
- 一次性脚本位于忽略目录 `outputs/metric_calibration_validation.py`，
  结果 `outputs/metric_calibration_validation_20261008.json`；未改动任何生产代码。
