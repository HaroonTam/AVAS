# E2 任务卡：同数据米制方案对照与选型

更新：2026-10-18。状态：21 条相对及 Metric 开发诊断已完成；未校正 Metric 全部偏远，正式标定、选型与生产接入尚未完成。
当前诊断步骤见 [预采集审查与相对深度诊断](e2_precapture_review.md)。
Metric 固定候选审查与下载/推理命令见 [Metric 候选步骤](e2_metric_candidate.md)。

用户选择的推进方式是先采集本机真值，对照相对深度自标定与 Depth Anything V2 Metric，
再决定生产采用哪条路线。用户已允许实验画面仅本地保存用于同图对照；
本文件不代表已批准下载权重或替换默认模型。F1 为分阶段决策；F2 已确认条件如下。

## 1. 目标与边界

在同一批本机画面、同一组目标框和真实距离上比较距离误差、有效覆盖率、失效情况和资源成本。
不预设 Metric 更准确，也不预设简单标定公式一定成立。两条路线都不通过时保持距离未知。
相对深度不能直接当米；紧急风险决策继续由确定性代码负责。

本任务不训练大型网络、不更改风险阈值、不把 E1 性能结果当作新模型性能。
1 m / 2 m 仍是未验证研究默认阈值；iBims-1 只作另一域流程验证，参数不得用于本机。

## 3. 真值定义与预采集

首先区分相机光轴方向的深度 Z、镜头到目标的斜距、地面水平距离。
不能把卷尺斜距直接当作离轴目标的 Z。第一轮在接近光轴的区域使用可测量平面目标，
固定相机与目标平面的几何关系，记录参考点及偏差；安装有俯仰时按实际几何处理。
未知内参时不声称已恢复三维欧氏距离。后续 E4 必须沿用并明确这个距离定义。

拟先用约 60×60 cm 或更大的哑光平面板，竖直正对镜头，在离地 26.5 cm 处标记对齐。
从镜头参考平面在地面的投影量到板前表面的投影，不从笔记本前沿起量；
镜头外壳参考点与光学中心的差异须记为不确定度。此方法依赖上述水平、正对安装条件。
建议 0.5、1、1.5、2、3 m 各 4 次独立摆放，约 20 条预采集记录，尚未执行。
普通板不保证被 YOLO 检出；人工板面 ROI 的测深诊断与后续生产检测框验证必须分开报告。
预采集核对真值、目标框、深度对齐、保存格式和无效原因。
预采集属于开发数据，不进入最终测试集。若真值定义无法与模型深度一致，先修正协议。
优先用静态、表面清晰的目标；椅子等非平面物体需说明真值对应哪个表面，
中心区域跨背景或多个深度表面时不能用一个随意选取的距离作为正确答案。

## 4. 正式采集与划分（建议规模，待预采集后冻结）

- 距离档建议 0.5、0.75、1.0、1.25、1.5、2.0、2.5、3.0、4.0、5.0 m。
  这是采样网格，不代表已验证范围；场地不足时缩小目标范围并如实记录。
- 起步目标：每档 18 次独立摆放，共约 180 个测距记录；分布在至少 9 个独立布景组，
  每组各距离约 2 次摆放。布景组包含不同背景、目标和光照，不只是同一画面改文件名。
- 按完整布景组预先分成拟合集 4 组、验证集 2 组、测试集 3 组，约 80 / 40 / 60 条。
  所有集合覆盖距离档；一次摆放的连拍、同段视频相邻帧必须进入同一集合。
- 每次摆放可保留 3 帧检查重复性，但视为一个相关采集组，不能宣称独立样本数翻三倍。
  数据量不足时报告小样本限制，不通过随机拆帧营造独立性。
- 明确加入遮挡、低纹理、反光、边界框跨背景及低照度等挑战记录，单独标记并报告；
  不因模型预测差而事后删除。真值确实不可可靠测量的记录保留为失效案例，不计距离误差。
- 测试集在选型前封存；若查看后继续调参，该批数据转为开发数据，另采新的独立测试集。

建议每条记录保存：sample_id、group_id、split、frame_id、时间、图像哈希、目标类别与框、
真值及单位、测量参考点与不确定度、安装版本、实际尺寸、光照/遮挡标签、配置和模型哈希。
图像和真实数据保存在独立的 outputs/e2_<运行标识>/，不覆盖旧运行、不提交 Git。
任何保存行为均需在采集入口显式开启，避免在正常运行中默认留存画面。

## 5. 公平对照的计算方法

先保存固定 YOLO11 版本产生的检测框，两个深度模型复用这些框，避免检测差异影响比较。
记录检测漏检；可另设人工框的测深诊断，但必须与生产检测框结果分表，不能混为整体能力。
沿用生产 [fusion]：center_region_median、inner_fraction=0.5、min_valid_pixels=9、
min_valid_fraction=0.5、trim_fraction=0.05；正式执行前按当时配置再次核实并冻结。
两条路线共用区域选择、像素过滤和统计流程，但按各模型语义处理无效值，不能把相对逆深度
的命名或转换公式直接套在 Metric 输出上。分别记录输入缩放、插值和原图网格对齐方式。

| 编号 | 候选 | 允许使用的数据 |
| --- | --- | --- |
| A1 | 相对深度统计 r，拟合 Z = a*r + b（affine-in-Z） | 只在拟合集估计 a、b |
| A2 | 拟合 1/Z = a*r + b，预测 Z = 1/(a*r+b)（affine-in-1/Z） | 只在拟合集估计 a、b；分母须为正且数值稳定 |
| B0 | 官方 Metric 原始米制输出，经相同区域统计 | 不使用本机真值拟合，作为未校正基线 |
| B1（可选） | Metric 结果的简单本机校正 | 如需增加，测试集启封前确定形式，仅用拟合集拟合 |

这里不进行神经网络训练；“拟合集”即标定参数训练数据。
A1、A2 及是否采用 B1 由验证集比较，不能用测试集挑公式。
相对模型的跨画面尺度/偏移不保证固定；映射不成立也是有效实验结论，不能强行产出米数。
官方 Metric 权重含室内/室外和不同规模；候选身份、许可与接口核对后才能运行。
来源：https://github.com/DepthAnything/Depth-Anything-V2/tree/main/metric_depth

## 6. 指标、选型与范围声明

对有效真值 Z_i 和预测值 p_i 报告：

- MAE = mean(abs(p_i-Z_i))，单位 m。
- RMSE = sqrt(mean((p_i-Z_i)^2))，单位 m。
- AbsRel = mean(abs(p_i-Z_i)/Z_i)，无量纲；真值必须正且有限。
- 绝对误差 p95、偏差 mean(p_i-Z_i)、最大误差、各距离档及场景分组误差。
- 有效覆盖率、拒绝率与逐原因计数；正偏差代表把目标估得更远，单列此类误差。

同时提供两模型共同有效样本的配对比较，以及各自对全量样本的覆盖统计。
不能通过拒绝难例获得更低 AbsRel 后就宣布胜出，也不能仅报幸存样本均值。
如估计置信区间，按独立采集组重采样；少量场景组下不作强泛化结论。

选型顺序：先检查真值/对齐/单位是否正确，再检查覆盖和失效是否符合研究用途，
然后以验证集 AbsRel 为主要比较指标，结合 RMSE、近距离过估、重复性及运行成本选择。
采集前与用户冻结可接受误差、最低覆盖率和性能要求；当前不虚构通用“安全合格线”。
差异不明确时报告证据不足，可补采验证数据，不能靠测试集反复择优。
选型后一次性用独立测试集评估，并报告失败项；测试未达预定要求时不得宣布可部署。

运行成本在同硬件、同精度、同输入设置下分别测量，分开记录预热和稳态、
推理计时边界、显存/内存与完整流水线吞吐率。双模型对照时的速度不代表单模型生产速度。
capture_to_dispatch 不是可听告警延迟。未运行的性能或准确率项均写“未测量”。

## 7. 生产接入与失效处理（选型后）

用户审阅对照结果后决定生产路线，随后才修改模型配置或接入米制适配器。
实现 app/fusion/metric_calibration.py 或最小等价适配，保留基线与回退路径。
Metric 路线也必须通过本机验证登记，不能仅凭模型输出单位就自动签发有效证据。
生产 MetricEvidence 仅由受控、有效的米制支持路径产生；拒绝任意 JSON 或 LLM 提供证据。

支持记录包含 support_id/版本、数据与划分哈希、模型/配置/安装身份、公式、参数、
输入统计支持范围、验证距离范围、测试误差和已知失效条件。
支持有效时才填米制字段；缺失记录、无效输入、非正结果、逆变换奇异、配置/安装不匹配、
超出标定输入支持范围或预测范围等情况返回 None 和原因。
不能只检查预测值落在区间内就宣称真实距离一定在区间内：单目预测仍可能误判域外目标，
该限制必须写入报告，不能承诺完美检测所有域外情况。

新增测试覆盖区间端点与外侧、NaN/Inf、非正距离、缺失/不匹配支持记录、
像素不足、跨帧/尺寸不匹配、米制字段传播与不可用降级；合成测试只验证代码逻辑。
所有新改函数具备完整注解和中文 docstring，不改变告警对 LLM/网络的独立性。
