## 测量对象与方法

- 测量生产 `SpeechWorker(WindowsSpeechBackend(rate=0))` 的 `submit()` 成功返回，
  到麦克风检测到扬声器声音的时间差。提交调用自身耗时另记；这不是场景采集到起声、
  识别延迟或完整播放时长，也不包含繁忙队列的排队实验。
- 每条之前等待 `wait_idle`，打开 48 kHz、单声道 float32 输入流；
  2.5 秒静音准备后提交，等待生产 worker 完成，再采集 0.5 秒。
  长文本等待最多两段 60 秒及 15 秒；未完成或后端报错时标记无效。
- 音频块为 960 样本，即 20 ms；基线范围为流启动后 0.5 秒至提交前 0.3 秒。
  RMS 阈值为 `max(0.001, 4 × 基线 RMS 的 p95)`，起声候选是提交后五秒内
  连续两个窗超过阈值的首窗起点。0.001 是归一化数字幅值，不是声压。
- 同时检查基线倍数 2 与 6 下的起声：缺失或差异超过 100 ms 判无效。
  输入状态异常、非有限音频、削波、提交前已有显著声音、时钟异常均排除。
  不因测量失败降低阈值；排除原因及未运行数量分别记录。
- 8 字符文本为 `距离信息不可用。`；16 字符为
  `环境风险无法完整评估，请您谨慎。`（原有 15 字符提示增加“您”，仅用于探针）；
  150 字符来自生产 `usage_help()`。不修改生产提示或风险规则。
- 若取得有效样本，按组和合并计算 mean、p50、p95、max；
  分位数采用 NumPy `percentile(method="linear")`，同时报告全部尝试及剔除数。
  每组仅 3 或 5 次，p95 不足以刻画稳定尾延迟，不能推广到其他机器或负载。

## 时钟、缓冲与误差

首次探针用 `inputBufferAdcTime` 加 PortAudio 流时钟到 `monotonic()` 的偏移，
偏移通过九次前后夹取中最窄区间估计。`stream.latency` 单独记录，**不再加到 ADC
采样时间上**；启动时刻加样本数和缓冲值的近似并未用于生成结果。
PortAudio 定义 ADC 时间为输入首样本的采集时间，流时钟与其同源，见
[sounddevice 时间戳与缓冲文档](https://python-sounddevice.readthedocs.io/en/0.5.3/api/streams.html)。

首次失败后读取本机 `time.get_clock_info`，发现 Python 3.12.9：

- `monotonic`：`GetTickCount64()`，报告分辨率 0.015625 秒；
- `perf_counter`：`QueryPerformanceCounter()`，报告分辨率 0.0000001 秒。

前者不足以支撑探针原来的 5 ms 映射检查。v2 改用 `perf_counter()` 记录提交、
回调到达和时钟映射；生产 `SpeechMessage.expires_at` 仍使用生产要求的
`monotonic()`，两种时钟不混算。`perf_counter` 适合短时长测量，见
[Python 3.12 文档](https://docs.python.org/3.12/library/time.html#time.perf_counter)。
这个修正不能解释或修复全部失败：ADC 时间间隔异常与音频未触发阈值仍需真机诊断。
v2 保持原有判据，新增每 200 ms 的最大 RMS 统计和异常时间间隔记录；诊断先测一条。

误差与局限须保留：

- 首次 API 报告输入缓冲 **40 ms**；该值是 API 估计，不是已校准绝对误差。
- 20 ms 窗造成起声定位粒度限制，40 ms 连续超阈要求可能漏掉或推迟弱起声；
  首个超阈窗不是精确的物理发声瞬间。背景声可产生假起声，需要安静环境和听感核对。
- 回调调度、音频驱动时间戳、时钟映射括区与漂移分别记录；本机 QPC 的高分辨率
  不等于整个测量链具有同等准确度。首次 ADC 连续性异常不能只归因于 Python 时钟。
- 麦克风到扬声器声程距离**未测量**，因此没有声程修正或可信的声程误差上界。
  测得的是声音到达麦克风的阈值时刻，不是用户耳边起声。
- 麦克风增益、音频增强、噪声抑制和回声消除状态未核实，可能影响捕获信号；
  尚未证明它们导致本次失败。
- 未测量场景采集到起声、感知并发负载、抢占时起声延迟或行走安全性。
